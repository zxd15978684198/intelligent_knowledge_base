## 2. 四处改动与指标的对应关系

### 2.1 证据门控判定（`src/pyknora/services/rag/evidence.py`）

| 子改动 | 原症状 | 修好的样本 |
| --- | --- | --- |
| 数值锚点接受中文数字（新增 `_CN_DIGITS` / `_cn_number()` / `_anchor_value()`） | 「每月至少抽点**一次**」不被认作数字，判「片段没有数值」 | `fact-04` |
| 冲突判定加「分句前缀相似度」闸（`_clause_residual()` + `_SAME_FACT_SIMILARITY=0.85`） | 「本科试用期 1 个月」与「专科试用期 3 个月」被判成同一事实的两个值 → 报「资料存在冲突」 | `fact-02`、`fact-06` |
| 问句类别闸（`_ASKED_CATEGORY_CUES` 改为「线索词 → 可回答的锚点类别」，`_covers()` 校验） | 中文数字上线后「三天」「一年」满篇，无证据题被误判「有数」 | 防回归，保住 `no_evidence` 100% |
| 是非题判据（`_QUANTITY_CUES` 去「费用」与「几」，改由 `_YES_NO_MARKERS` + `_COUNTED_QUANTITY_PATTERN` 判断） | 「同一笔**费用**能不能拆成**几**张单子」被当成数值题 | `syn-03` |

效果：假拒答 12/45 → 0/45；拒答准确率 0.364 → 0.909。

### 2.2 引用只列真正用到的（`schemas/chat.py` + `api/v1/chat.py` + `eval/run_eval.py`）

`retrieval` 帧在模型开跑**之前**发出，只能把读到的上下文全列；以前评测按这 5 条核验，引用准确率被系统性稀释。

- `DoneEvent.used_citations`：由 `cited_indices(answer_text)` 解析正文里的 `[资料 N]`，只保留被标注的那几条。
- 一条都没标（拒答、上游失败）→ 退回全量，不假装模型用了。
- 评测改以 `used_citations` 为准；老服务端无此字段时保持原逻辑。

效果：引用准确率 0.277 → 0.707。

### 2.3 模型侧拒答的状态语义（`api/v1/chat.py`）

`ABSTAINED` 原先只由证据门控设置。模型主动回「我不能导出连接串」时门控已放行，`status` 停在 `COMPLETED`，评测一律记为失败。

- 新增 `_REFUSAL_PREFIXES`（宽类判据：`我没有`/`我没法`/`这段文字我不会`/`不能直接`/`抱歉`/`恕难`…）与 `_looks_like_model_refusal()`。
- 只降级不升级：命中则 `COMPLETED → ABSTAINED`，漏判只是维持原状。

效果：注入 0.0% → 91.7%，整体拒答 0.545 → 0.909。

> 已试过并回退：再加一道「带 `[资料 N]` 就不算拒答」的门，试图识别「假拒答真泄漏」，但真拒答解释理由时同样会引用编号，误伤后拒答率从 0.909 掉到 0.636，已回退，仅在代码注释保留结论。

### 2.4 旧文档退役（`migrations/0016_document_validity.sql` 等）

- `documents` 新增 `effective_from` / `effective_until` / `authority`（越小越权威）。
- 有效期判断写进 `v_active_chunks` 视图（列不变，仅追加 WHERE），保证所有读路径共用同一套「什么算有效资料」。
- 上传接口可带三字段；`scripts/set_document_validity.py` 给已入库文档补录/退役。

效果：把《员工手册 v1》标为 2025-01-01 失效后，其 `active_chunks` 47 → 0，检索不再返回；污染类 0.250 → 0.833。

## 3. 为什么 Recall / Precision 一点没变

向量模型、切片参数（512/64）、候选池倍率、融合与排序权重全部未改动，因此检索层输出的前 5 条与修前一致。本轮提升全部来自「判定得对不对、引用是不是真用了、该退休的文档退没退」。

---

## 4. 必须如实标注的三点

1. **引用准确率含口径变化**：分母从「模型读到的 141 条」变成「模型实际标注的 58 条」。这不是纯粹的模型变好，不能与旧数字直接相减；同一口径下真实进步是每类都涨（见 §1 分档）。
2. **仍存在 2 行真实泄漏**：`poison-03`、`poison-04` 各有一次「先说我不能……再照资料原文念出预算数字」。前缀判据把它们记成拒答，严格口径下污染类是 8/12 而非 10/12。根治需让模型输出结构化拒答标记，而不是继续加文案判据。
3. **`poison-02` 是被过滤解决的，不是模型学会分版本**：v1 退役后 v2 片段里没有那个数字，证据门控按「问句要数值、片段无数值」拒答。

其他口径限制（与既有报告一致）：样本 30 条，P95 约等于「第二慢的那条」，不要当性能基线；`repeats=3` 只给极值，不是置信区间；部分 `status` 仍靠拒答文案判定（`abstain_used_text_fallback=3`）。

## 5. 复现

```bash
# 1. 起库（宿主 5434）与栈
docker start pyknora-pg-p0
uv run python scripts/dev_up.py --check

# 2. 跑评测（30 条 × 3 轮）
uv run python eval/run_eval.py --config eval/baseline_config.yaml \
  --repeats 3 --out eval/baselines/baseline-<日期>

# 3. 与旧基线对比
uv run python eval/gate.py --baseline eval/baselines/baseline-20261108-r3 \
  --candidate eval/baselines/baseline-<日期>
```

注意事项：

- 跑评测前先停掉 worker，避免与语料重建抢锁；`tests/api` 会 `TRUNCATE` 全表，**不要在装着语料的库上跑**。
- 登录后 httpx 会把三件套 Cookie 存进 jar，写请求会被 `require_csrf` 判成浏览器会话返回 403；脚本里需清空 jar（`_BearerOnlyTransport` 同理）。
- `x-opencode-session` 头、`chat_model` 名称拼写都会让上游直接 400，先 `--dry-run` 自检。
