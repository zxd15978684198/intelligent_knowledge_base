### 1.3 20 条是怎么来的

#### 配额（`build_eval_set.py:76-83` 的 `QUOTA`）

`fact 6 + exact_term 4 + synonym 3 + no_evidence 3 + deny 2 + version 2 = 20`。
`--check` 会逐类比对配额，不符即报错（`:1016-1024`）；**改配额等于改验收口径**，必须同步改计划。

#### 六类各问什么（定义 + 本项目真实样本）

| category | 定义（考什么） | 真实样本 |
| --- | --- | --- |
| `fact` | 单一事实落在同一片内：金额、期限、数量。答对不靠改写，靠找到那片。 | `fact-01` 注册资本「五百万元」；`fact-05` 移交清册「一式三份」 |
| `exact_term` | 必须原样复述的术语/编号；改一个字即算错。 | `exact-01`「统一领导、分级管理」；`exact-04` 档案编号前缀「HL-DA」 |
| `synonym` | 问句是口语/同义改写，原文是书面语，字面重合低。 | `syn-02`「几号发工资」→ 原文「付薪日期」；`syn-03`「拆成几张单子」→「严禁分拆」 |
| `no_evidence` | 语料里**真的没有**这件事，正确行为是拒答。 | `noev-01` 食堂午餐收费；`noev-03` 自住房无息借款 |
| `deny` | A 区令牌问 B 区 KB，期望 403/404 且响应体无片段。 | `deny-01` 研发中心预算总额；`deny-02` 机房扩容预算 + 执行期限 |
| `version` | 同名文档重传后（v2 生效，`active_index_version=2`），只能拿现行版作答。 | `ver-01` 春节休假；`ver-02` 固定资产「2000 元以上」 |

> `deny`（没权限）与 `abstain`（没证据）**绝不混用**（`build_eval_set.py:84`）：前者测 404 不泄漏存在性，
> 后者测 200 + `ABSTAINED`。混用会让「权限拦截率」与「拒答准确率」互相掩盖。

#### gold 回填规则（人只写题，机器回填）

1. **人写种子题**：`query` + `expect_facts` + `locator`（原文里连续、可唯一认出的一段字），见 `Seed` `build_eval_set.py:96-105`；
2. **匹配前去空白**：PDF 每 ~40 字断行，同一条款常被 `\n` 劈开，所以 `re.sub(r"\s+", "", s)` 后再做子串匹配（`:13-18`）；
3. **多命中取最小 `chunk_ordinal`**：`chunk_overlap=64` 会让同一句同时落在相邻两片，取最小序保证产物确定，0 命中才报错（`:20-24`、`:673-674`）；
4. **回填三段组合键**：`corpus`（人读）+ `document_id`（权威定位，来自 `.tmp_ref/eval_setup.json`）+ `chunk_ordinal`（0 起）+ `content_sha1_8 = sha1(片正文)[:8]`（`:657-687`、`sha1_8()` `:356-358`）；
5. **回填后再读一次 `GET /documents/{id}`**：gold 必须落在**现行**活动构建上，否则一次重传之后 gold 指向已退休的 build，`Recall` 会安静地变成 0（`:26-31`、`_verify_snapshot` `:605-630`）；
6. **结构校验**：`chunk_ordinal` 必须是 0 起整数，`content_sha1_8` 必须是 8 位小写 hex（`:866-896`）；
   `--check` **只验结构**（配额/字段/gold 非空），不证明 gold 仍指向库里的活动切片（`:33-37`）。

#### 一条记录一个 gold：跨文档/跨问法一律拆条

- 15 条 `answer` 的 `gold_chunks` 长度**全为 1**（`--check` 逐条打印 `corpus#ordinal@sha1`）；
- 同一片被两个问法用到 → 拆成两条记录，而不是共享 gold：`fact-06` 与 `ver-01` 同为
  `员工手册v2.docx#8@a169a6e8`，前者问探亲假天数、后者问春节起止；
- 答案跨两处时**拆成两条记录**，不在一条里塞两个 gold——否则 `Recall@5` 的分母变成 2，
  与其他样本不可比；
- 术语被 PDF 跨行截断时，`expect_facts` 只取能落在**同一片**内的部分：`exact-02` 原文四项
  「上下结合、分级编制、逐级汇总」，因为「逐级汇总」跨行，只保留前两项（该条 `notes` 自述）；
- 两条 `deny` 同指 B 区同一篇《财务内部预算.md》，但一条测**金额**（1200 万）、一条测**期限**
  （78 万 + 2026-09-30 前执行完），覆盖两类最容易泄漏的面。

结果：`Recall@5` 每条样本的分母恒为 1，`Precision@5` 每条样本的天花板恒为 1/5。
这两个事实直接决定了 §6.1 的口径讨论——**不是数据缺陷，是设计选择**，但必须在报告里说清。

#### `content_sha1_8` 的作用（三层，别混）

1. **指标的唯一匹配键**：`recall_at_5()` 用 `results[].content_sha1_8`（runner 现算，`run_eval.py:696`）
   与 `gold_sha1_8`（`:311`）求交集（`:876-881`）；`precision_at_5()` 同样只按 sha1 计命中（`:884-894`）。
   `document_id` / `chunk_ordinal` **不参与指标匹配**，它们负责可读定位与引用核验的 gold 文档集（`:315`）；
2. **区分「序还是那个序、内容已经变了」**：切片参数从 512/64 改掉后，`chunk_ordinal` 照样存在，
   只有正文指纹能发现漂移（计划 `:182`；`build_eval_set.py:6-8`）；
3. **它只管切片正文，不管源文件**：文件级一致性由 `eval/corpus_manifest.json` 的 sha256 负责
   （`eval/corpus.py:367-371` 的 `--verify-only`）。两层各管一段，缺一层就会把「文件换了但 index 没重建」
   误读成模型退化。

## 4. 指标口径（8 个数值键）

定义来源：`eval/run_eval.py:1032-1041` 的 `METRIC_DEFINITIONS`（runner 原义，不是本文件重写）；
每个键的值、min/max、per_repeat、分母都在 `summary.json` 里。

### 4.1 逐键定义、分母与空集行为

| 键 | 定义（runner 原文） | 分母（`counts.*` / 变量） | 空集返回 |
| --- | --- | --- | --- |
| `recall_at_5` | 命中 gold 的条数 / gold 条数 | `recall_samples`（本轮 15） | gold 为空 → `None`，**不进平均** |
| `precision_at_5` | 命中条数 / `min(5, 返回条数)` | `precision_samples`（本轮 15） | gold 为空 → `None`；gold 非空但返回 0 条 → **`0.0`**（`:889-892`，不是 None） |
| `citation_accuracy` | 通过规则核验的引用数 / 被核验引用总数（仅 answer 类样本） | `citations_checked`（逐条引用，非样本；baseline 45 / candidate 44） | checked=0 → `None`（`:994`） |
| `abstain_accuracy` | no_evidence 样本中判为 `ABSTAINED` 的比例 | `abstain_samples`（3） | 无 abstain 样本 → `None` |
| `deny_interception` | deny 样本中两端点均 403/404 且响应体无片段的比例 | `deny_samples`（2） | 无 deny 样本 → `None` |
| `retrieval_p95_ms` | 单次 `/query` 端到端延迟的 P95（nearest-rank） | 有 `latency_ms` 的样本数（20） | 无延迟样本 → `None` |
| `chat_ttft_p95_ms` | `/chat` 首个 token 到达耗时的 P95 | 有 `chat_ttft_ms` 的样本数（20） | 同上 |
| `chat_total_p95_ms` | `/chat` 到 `done` 事件的总耗时 P95 | 有 `chat_total_ms` 的样本数（20） | 同上 |

三条容易误读的细节：

- **引用准确率的分母是「引用条数」不是「样本条数」**：15 条 answer 样本共产出 45 条引用
  （平均 3.0 条/样本），所以 16/45 = 0.3556；候选 14/44 = 0.3182。改上下文条数会同时改分母，
  两侧的 0.356 与 0.318 **不能**直接读成「引用质量」的单变量对比（见 §6.6）；
- **P95 用 nearest-rank**：`rank = (95*n + 99)//100`，n=20 时取排序后第 19 个——它等于某一条的
  真实观测值，不是插值（`:827-838`）。所以 375.14 / 211.75 其实各是「第 19 慢那条」的延迟；
- **`None` 不等于 0**：空集一律返回 `None` 并打印「为什么是 None」（分母缺失），
  `compare-20261030.md:203` 把这条写成硬规则——「0 是一个实测值，不是不知道」。

## 5. 样本数口径（最容易说错的一处）

`eval/run_eval.py:1010-1015` 的注释已把话说死：

- `counts.samples` = `raw.jsonl` 行数（**含 repeats**）；
- `counts.unique_samples` = 评测集条数（去重后）。

**禁止**把 `--repeats 3` 的 60 行写成「60 条样本」。报告开头写样本数必须用 `unique_samples`。
本轮两侧 `samples = unique_samples = 20`，所以这条规则本轮不构成风险，但下一轮 `repeats=3` 一定踩。

## 6. 哪些做法会让指标失真（虚高 / 虚低 / 看着精确其实不精确）

每一条都给了本轮的真实数值或代码位置，不是假设。

### 6.1 gold 只标 1 片 → Precision 上限恒为 1/5

15 条 `answer` 每条只有 1 个 gold，而 Precision 的分母是 `min(5, 返回条数)`，返回 5 条时
**天花板 = 1/5 = 0.200**。两轮都正好 0.200，说明 15/15 全部命中——这一列**没有区分力**，
不能读成「精度低」，也不能读成「检索差」。若把 gold 补成真实的 5 片（答案确实覆盖 5 片），
同一份检索结果会变成 1.000。补齐 gold 是 v0.2 的事，必须先冻结重跑基线。

### 6.2 Recall@5 = 1.000 也不说明检索好

每条 gold 只有 1 片、且 15 条全命中，`15/15 = 1.000`。天花板现象同上：这一列在本轮同样
**没有区分力**（`per_category` 里有 gold 的 4 个类别——`fact`/`exact_term`/`synonym`/`version`
——全是 1.000，`no_evidence` 与 `deny` 是 `null`）。它唯一能证明的是「gold 定位与切片没漂」，
不能证明「候选策略检索得好」。

### 6.3 gold 不校验 sha1 → 重切后仍记「命中」（虚高）

若只看 `document_id + chunk_ordinal`，切片参数一改，ordinal 还在、内容已换，Recall 仍记命中。
本项目用 `content_sha1_8` 做匹配键（`:876-881`）正是为了避免这种「假命中」；
反过来，若有人图省事把 gold 的 sha1 写成文件 sha256 或前 8 位大小写混写，`--check` 会直接报错
（`:866-896`），不会静默。

### 6.4 `abstain_used_text_fallback` 的计数口径比名字宽（本轮实测踩到）

`counts.abstain_used_text_fallback` 的定义是「abstain 样本里 status **不是** `ABSTAINED` / `ANSWERED`
的条数」（`:1023-1027`）——它把 `COMPLETED` 也算进去了。本轮 baseline 记 1、candidate 记 2，
数值恰好等于「拒答失败条数」，但 `summary.json` 的 warning 写的是「status 缺失，已退化为文案匹配」。
**核对 raw 后的事实是：那两条的 status 是 `COMPLETED`，不是缺失**（`compare-20261030.md:91-92`），
也就是说「文案兜底」本轮根本没被用到。影响：这句 warning 会让读者以为判定靠的是关键词，
实际靠的是 `status`。修法在 runner（`eval/*.py` 不在本文件写范围），本轮只登记，不改数。

### 6.5 `expect_facts` 是字面子串匹配 → 空格差异造成假失败（虚低）

`FACT_MISSING` 的判定是 `fact in answer_text`（`:1139`）。`fact-03` 的期望是「50元」，
模型答「50 元」即判失败：candidate 的 `fact-03` 事实命中 1.000 → 0.000（`compare-20261030.md:120`），
而 04 已判它是**口径伪影**，不是模型变差。反向的坑同样存在：把 `expect_facts` 写成「元」
就会必中，指标虚高。

### 6.6 引用准确率对「上下文条数」敏感 → 分母一变，结论就变

分母是逐条引用（45 / 44 条，平均 ~3 条/样本）。supporting 放宽 → 引用条数涨 → 分母变大；
supporting 收窄到 1 条 → 分母变小、少数错引权重变大。本轮引用准确率从 0.3556 掉到 0.3182，
分子 16→14、分母 45→44 **同时**变化，其中 `exact-02` 的下降已被 04 §4.1 判为「分母变化」成分。
所以这一列只能「连同分母一起读」，不能单独当引用质量。

### 6.7 用 `--limit` 或 `embedding_backend=hashing` 的产物对外

这两类 run 的 recall 是自证：`--limit` 只跑前 N 条，`hashing` 后端根本不语义检索。
`compare-20261030.md:145` 已写死「`embedding_backend=hashing` 或 `--limit` 的产物不得对外」。
本轮两侧 `embedding_backend=local`、`raw_lines=20`，符合对外条件。

### 6.8 `repeats=1` 的 min/max 被当成「稳定」

两侧 `min == max == value`，只说明跑了一次。`compare-20261030.md:130` 与 `:135` 都写明
「波动无意义」。若把 min==max 写成「结果非常稳定」，是把「没测」冒充成「测了」。

### 6.9 P95 用 20 条样本 → 等于「第二慢那条」

n=20 的 nearest-rank 取第 19 个，换一条样本就能让 P95 变动几十 ms。「检索快了 163 ms」
只能读成「这一次的第 19 慢样本快了 163 ms」，不能当性能基线（`compare-20261030.md:129`）。

### 6.10 把 no_evidence / deny 算进 Recall / Precision 的分母

若用「20 条」做分母，Recall 会从 1.000 被稀释成 0.750（15/20），Precision 同理。
runner 已经按 `gold 为空 → None 且不进平均` 处理（`:878-881`），但报告里若不自报分母，
读者会用 20 去反推，得出一个不存在的数。
