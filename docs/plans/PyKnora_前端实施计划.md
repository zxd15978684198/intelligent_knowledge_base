# PyKnora 前端升级计划（P0 审定版）

> 状态：**已审定（P0 基线）**，2026-11-01 由用户逐项确认后定稿。
> 本文件取代同名旧版 Next.js 计划（原"待评审"草案已废弃，历史见 git 记录）。
> 定位：基于当前 FastAPI 能力**新建**前端，不是改造已有界面。当前仓库没有业务前端，只有 FastAPI 自带的接口文档。

---

## 0. 已确认的核心决策

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 交付目标 | **P0 产品闭环**：可演示、可回归，自动化测试与视觉可访问性是完成条件，不是加分项 |
| D2 | 功能范围 | 核心知识闭环 + 基础成员管理；排除后端尚无契约或刻意暂缓的模块（见 §1） |
| D3 | 后端改动 | 仅补一项只读 `filename` 字段及测试；不改鉴权、上传、索引、权限语义 |
| D4 | 鉴权 | 保留 Bearer JWT + `localStorage`，作为 P0 受控折中；生产化再升级 Cookie/刷新令牌 |
| D5 | 状态管理 | TanStack Query 管服务端数据；Context 只存认证与工作区；聊天用独立 `useReducer` 状态机 |
| D6 | 视觉方向 | **浅色"证据工作台"**：答案与引用并置，冷中性色 + 单一深青强调色 |
| D7 | 样式技术 | Tailwind CSS + CSS 变量语义令牌 + shadcn/ui（Radix）+ Phosphor Icons |
| D8 | 契约策略 | OpenAPI 生成为主；错误信封与 SSE 事件手写补充，关键流用 Zod 运行时校验 |
| D9 | 聊天失败语义 | 不自动重放、不伪装续传；断流保留半截回答并显式标记"不完整" |
| D10 | 验收门禁 | 静态检查、契约/组件测试、浏览器主链路、视觉可访问性四类全部强制 |

## 1. 范围

### P0 纳入

- 注册、登录、身份验活和权限感知。
- 知识库列表、创建、改名、删除。
- 文档上传、列表、切片、血缘、删除和作业轮询。
- 混合检索调试、单轮流式问答、引用与证据状态。
- 成员列表、邀请、角色调整、移除。
- 自动化测试、响应式和可访问性验收。

### P0 排除

- Agent、Wiki、采集、多轮会话、模型管理。
- 角色权限编辑器、所有权转移、索引重建页面。
- 聊天断线续传、自动重试。
- i18n、暗色主题、SSR 数据获取。

### 允许的后端改动（仅此一项）

- 在文档列表与详情响应中增加只读 `filename` 字段。
- 优先从现有版本信息读取，不预设新增数据库列。
- 补对应后端接口测试和 OpenAPI 快照。
- 其余切片全文定位、会话持久化等后端改造不进入 P0。

## 2. 技术选型与架构

| 领域 | 决定 | 实施口径 |
| --- | --- | --- |
| 框架 | Next.js App Router + TypeScript | 静态壳保留在服务端，依赖浏览器令牌的业务页使用客户端组件 |
| 接口连接 | 同源 `rewrites` 代理 | 将 `/api/:path*` 转发到 FastAPI，避免为首轮另加宽松跨域配置 |
| 服务端数据 | TanStack Query | 负责缓存、失效刷新、轮询和错误重试；查询键必须包含工作区 |
| 本地状态 | Context + `useReducer` | Context 只保存认证与工作区；聊天使用独立状态机，不引入全量全局状态库 |
| 鉴权 | Bearer JWT + `localStorage` | 统一处理 401 清理登录态；生产化再升级 HttpOnly Cookie 与刷新令牌 |
| 样式 | Tailwind CSS + CSS 变量 | 组件不直接写品牌色，统一引用语义令牌 |
| 组件 | shadcn/ui + Radix + Phosphor | shadcn 作为可修改源码，不保留默认皮肤；不引入 GSAP、Framer Motion |
| 契约 | OpenAPI 生成 + Zod 补充 | 普通接口生成类型；错误信封和 SSE 事件手写判别类型并做运行时校验 |
| 测试 | Vitest、Testing Library、MSW、Playwright、axe | 单元、接口模拟、真实浏览器和可访问性分层覆盖 |

## 3. 页面与目录规划

页面采用"知识库工作区"结构，文档、检索和问答共享当前知识库上下文：

```text
web/
├── app/
│   ├── (auth)/login/page.tsx
│   ├── (app)/layout.tsx
│   ├── (app)/kbs/page.tsx
│   ├── (app)/kbs/[kbId]/layout.tsx
│   ├── (app)/kbs/[kbId]/documents/page.tsx
│   ├── (app)/kbs/[kbId]/documents/[documentId]/page.tsx
│   ├── (app)/kbs/[kbId]/query/page.tsx
│   ├── (app)/kbs/[kbId]/chat/page.tsx
│   └── (app)/settings/members/page.tsx
├── components/ui/                 # 按钮、表单、表格、弹窗、骨架屏等基础组件
├── features/
│   ├── auth/                      # 登录、注册、身份验活、权限控制
│   ├── kbs/                       # 知识库表单、列表与乐观锁操作
│   ├── documents/                 # 上传、文档表格、切片和血缘
│   ├── jobs/                      # 五态徽标、轮询与取消
│   ├── query/                     # 检索调试和双路排名
│   ├── chat/                      # 流式回答、引用栏和终态展示
│   └── members/                   # 成员邀请、角色调整与移除
├── lib/
│   ├── api/                       # 客户端、请求头、错误和分页适配
│   ├── contracts/                 # 生成类型、SSE 类型、Zod 校验
│   └── auth/                      # 令牌与权限工具
├── styles/                        # 全局样式和设计令牌
├── contracts/openapi.json         # 可复验的接口快照
└── tests/                         # unit、contract、e2e
```

## 4. 组件拆分原则

| 层级 | 组件 | 职责边界 |
| --- | --- | --- |
| 基础组件 | Button、Field、Dialog、Table、Tabs、Toast、Skeleton、StatusBadge | 只处理外观和通用交互，不直接请求接口 |
| 文档组件 | UploadPanel、DocumentTable、ChunkList、LineageTimeline | 上传与列表分离；文档详情组合切片和血缘 |
| 作业组件 | JobBadge、JobPoller、JobCancelButton | 只认五态和 `terminal`，不伪造百分比进度 |
| 检索组件 | QueryComposer、RetrievalTable、DegradedBanner | 展示融合分数、向量排名、关键词排名和降级原因 |
| 聊天组件 | ChatComposer、StreamingAnswer、CitationRail、AnswerStatus | 流式状态机与展示分离，引用支持双向定位 |
| 权限组件 | PermissionGate、DisabledReason | 根据权限点控制体验，不替代服务端授权 |

## 5. 接口与关键交互实现

- **统一客户端**：集中注入 `Authorization` 和可选 `X-Workspace-ID`；上传由浏览器生成 multipart 请求头，不手工设置。
- **写操作**：知识库修改和删除携带 `If-Match`；上传携带 `Idempotency-Key`；冲突后重新读取最新版本，不静默覆盖。
- **分页适配**：知识库使用游标；文档使用带全量总数的偏移分页；切片使用"加载更多"，不能把页内条数当总数。
- **上传分支**：202 开始轮询；200 且 `deduped=true` 直接提示重复并停止，不创建空轮询任务。
- **作业轮询**：页面可见时按间隔执行，终态立即停止；失败展示 `error_code` 和重新上传入口，取消不承诺立即停止处理中任务。
- **流式问答**：使用 `fetch + ReadableStream`，解析跨网络分块和换行差异；依次处理 `retrieval → token* → done`，`error` 后仍等待最终 `done`。
- **断流**：切换问题、知识库或离开页面时中止请求；半截回答标记"不完整"，不自动重放、不宣称续传。
- **异常处理**：401 清理登录态；403 显示缺少的权限；404 显示"不存在或无权限"；410 重新加载第一页；500 展示请求标识便于查日志。

## 6. 视觉与交互规范

采用已确认的**浅色证据工作台**：

- 冷中性背景、白色内容面、深青色单一强调色；成功、警告、失败使用独立语义色并配文字或图标。
- 中文使用清晰无衬线字体，标识符和代码使用等宽字体；表格数字启用等宽数字。
- 桌面端为带文字标签的侧栏；问答页采用"回答主栏 + 证据侧栏"，窄屏将证据栏折为标签页或下方区域。
- 页面标题保持工具界面尺度，不设置营销页大标题、虚拟指标卡、渐变、玻璃拟态或自动播放动画。
- 普通过渡控制在约 150–250ms，仅表达状态变化；支持 `prefers-reduced-motion`。
- 所有交互具备默认、悬停、焦点、按下、禁用、加载和错误状态；正文对比度至少 4.5:1，移动端主要触控目标至少 44px。

## 7. 分阶段实施与验收

测试应随各阶段同步交付，不能全部堆到 F6。实际施工时，每个阶段还需按仓库规范更新进度表和实施状态文件。

| 阶段 | 主要工作与交付 | 完成判据 |
| --- | --- | --- |
| F0 契约基线 | 补 `filename`、保存 OpenAPI 快照、生成类型、整理 SSE 和错误样例 | 后端接口测试通过；生成类型可复现，漂移会失败 |
| F1 工程与设计底座 | 前端脚手架、代理、令牌、应用壳、基础组件和测试框架 | 生产构建通过；三档宽度的空壳无横向滚动 |
| F2 认证与知识库 | 登录注册、验活、权限上下文、知识库完整管理 | 刷新保持登录；401、游标失效、版本冲突均有正确恢复路径 |
| F3 文档与作业 | 上传、列表、切片、血缘、轮询、取消和删除 | 好文件、坏文件、重复文件、超限文件及五态均有自动化用例 |
| F4 检索与问答 | 检索调试、流式状态机、引用、降级和全部回答终态 | 正常、拒答、预算中止、错误后终态、主动中止和断流全部通过 |
| F5 成员管理 | 成员列表、邀请、角色调整、移除和按钮权限 | 不同角色看到正确可用性；服务端越权仍被拒绝 |
| F6 总体验收 | 浏览器主链路、视觉审查、可访问性、启动文档和证据归档 | 四类强制门禁全部通过，无未解释的 FAIL |

## 9. 最终交付物与总验收

最终应交付：完整 `web/` 工程、设计令牌与组件库、接口快照和生成类型、SSE 解析器、后端 `filename` 补项、单元与契约测试、Playwright 主链路、三档截图及检查记录、启动与验证书面说明。

总验收必须同时满足：

- 生产构建通过。
- 前端自动化全部通过。
- 后端相关测试通过。
- 真实主链路可走通。
- 异常分支不伪装成功。
- 三档宽度无横向溢出。
- 键盘与对比度检查通过。
- 设计检查无未解释失败。
