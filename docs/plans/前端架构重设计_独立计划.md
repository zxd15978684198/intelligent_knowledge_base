## 1. 这份计划要达成什么

- **目标**：重新设计并编写前端架构——产出一份完整的架构设计文档，并据此重构前端代码；鉴权会话升级是其中一个子项目，允许配套改后端，但改动严格受 §3.2 约束。
- **主交付**：一份架构设计文档（第 4 节八章）。
- **后续交付**：分阶段实施计划 + 按新架构落地的前端代码 + 白名单内的后端配套改动。
- **总口径（用户已裁决）**：允许改后端，但**只许落在 §3.2 的白名单内**；白名单之外一律不动。

## 2. 范围与边界（自包含）

- 可写：前端目录内的页面、组件、状态、数据层、测试、构建配置与前端文档；以及 §3.2 白名单列出的后端文件与新增文件。
- 不做：不做权限角色模型扩展、不做服务端首屏取数改造、不做可观测性埋点、不做持续集成与容器交付加固——这四个是其它子项目，本次不混进来。

- 不做：不把已确认的四项决策重新论证、不逐节展开成施工级规格、不翻查与白名单无关的目录。

## 3. 四项已确认决策（原样保留，作为设计输入）

### 3.2 四项决策的修改边界（唯一白名单）

> 读法：每条决策给出「允许改什么 / 明确不改什么 / 收口理由」。允许改的项精确到文件与改动点；没列到的文件一律不动。

**决策 ① · 后端直供 Cookie**

| 允许改 | 明确不改 |
| --- | --- |
| `src/pyknora/api/v1/auth.py`：现有注册/登录端点加响应参数下发会话 Cookie；**新增**刷新端点、登出端点、一个只含有效期的刷新响应模型、两个 Cookie 读写私有 helper | 注册/登录/查我三个端点的既有响应字段一个不改；登录失败与重名冲突的既有语义不改；不新增令牌种类；`src/pyknora/services/auth/jwt.py` 的签发/校验函数原样复用 |
| `src/pyknora/core/settings.py`：追加一个会话有效期配置 + 一个「是否强制安全 Cookie」的判定属性 | 既有配置项、既有生产密钥校验逻辑不改 |
| `.env.example`：补一行会话有效期配置 | 其余配置行不动 |

收口理由：这一步只解决「令牌从响应体搬到 Cookie」，不触碰令牌本身的算法与既有业务语义。登录响应体保留访问令牌是显式取舍，供命令行工具与评测脚本继续使用。

**决策 ② · 落库 + 单次轮换 + 重用检测**

| 允许改 | 明确不改 |
| --- | --- |
| **新建** `migrations/0015_refresh_tokens.sql`：一张会话令牌表（存令牌哈希、会话家族、主体、CSRF 哈希、绝对过期时间、轮换时间、后继哈希、撤销时间）+ 两个索引；只追加新号段 | 已存在的 14 个迁移文件一个不改；不改写既有视图与既有表；不加工作区列、不给后继哈希建自引用外键 |
| **新建** `src/pyknora/db/repos/refresh_tokens.py`：一个仓储类，六个方法（行锁读取、插入后继、标记轮换、撤销家族、查活跃后继、清理过期） | 不复用/不修改其它仓储；不引缓存或消息队列 |
| `src/pyknora/models/tables.py`：**末尾追加**一个表映射类 | 文件内既有映射类、历史注释一律不动 |
| **新建** `scripts/purge_refresh_tokens.py`：手动清理过期行的运维脚本 | 不引调度器 |
| `tests/api/conftest.py`：隔离清理的表清单加一行新表名 | 夹具其余逻辑不动 |

收口理由：这一步只新增「会话令牌」这一块独立存储，不碰文档、切片、索引、向量、发布事务等任何既有数据链路；过期行靠顺带清理 + 手动脚本，不引入新基础设施。

**决策 ③ · 401 触发 + 单飞队列 + 原请求重放**

| 允许改 | 明确不改 |
| --- | --- |
| 前端数据层：新增刷新会话函数（模块级单飞 + 跨标签页选主）、401 后原请求重放一次、失效时跳转登录 | **后端零改动**（刷新端点归决策 ①，本决策不新增任何后端逻辑） |
| 前端会话层：登出改为触发幂等登出端点 + 跨标签页广播；首屏总是探活一次 | 上传请求与已开流的流式应答**明确排除**重放；刷新端点自身失败不再嵌套刷新 |
| 前端状态层：删掉本地令牌存储与「令牌即登录态」的判据，改以会话状态为唯一真值源 | 状态机里「出错后仍要等结束事件」这条既有不变量不动 |

收口理由：续期是**前端调用纪律**，后端只被动提供一个刷新端点；把重放逻辑放前端，才不会把「单飞」扩散成后端中间件。并发必须单飞，否则会误触发决策 ② 的重用检测，把整个会话家族撤销。

**决策 ④ · SameSite=Lax + 双提交 CSRF Token**

| 允许改 | 明确不改 |
| --- | --- |
| `src/pyknora/core/errors.py`：追加一个 CSRF 失败错误码 + 一条 403 映射 | 既有错误码集合与状态码表其它条目不动；新码不进可重试集合 |
| `src/pyknora/api/deps.py`：**末尾追加**一个 CSRF 校验依赖；令牌解析函数**只换三行**（有 Cookie 用 Cookie、无 Cookie 才回退到 Bearer 头）；文件头注释同步改写 | 工作区选择逻辑、成员校验、数据库上下文设置、请求上的作用域对象、权限与知识库访问校验全部原样；解析失败的错误文案原样保留 |
| `src/pyknora/api/main.py`：8 个非鉴权路由注册处各挂一行 CSRF 依赖 | 鉴权路由注册处不挂；异常处理器、请求 ID 中间件、注册顺序全部不动 |

收口理由：改成 Cookie 后浏览器自动携带才出现跨站伪造风险，所以补一层校验依赖；但身份解析与权限仍只有一个入口，CSRF 不另起一套身份判断。CSRF 值按会话稳定、不随刷新轮换，否则决策 ③ 的重放在途请求会全部带旧值失败。

### 3.3 全局封顶（防止跑偏）

**前端侧（决策 ③ 的落点）**
- 允许改：数据请求层、会话层、鉴权状态层、流式应答的建流段、成员域的鉴权传参，以及对应的前端测试。
- 删除项仅限：本地令牌存储模块及其单元测试。
- 明确不改：状态机里「出错后仍要等结束事件」的不变量、路由与渲染结构、代理转发配置、构建产物模式、组件与样式层、其它子系统的取数逻辑；上传请求与已开流的流式应答明确排除重放。

**后端侧（决策 ①②④ 的落点）**
- **允许改的既有文件，仅此 8 个**（后端源码 6 + 测试夹具 1 + 配置样例 1）：`src/pyknora/api/v1/auth.py`、`src/pyknora/api/deps.py`、`src/pyknora/core/errors.py`、`src/pyknora/core/settings.py`、`src/pyknora/api/main.py`、`src/pyknora/models/tables.py`、`tests/api/conftest.py`、`.env.example`（按改动点逐一对应 §3.2，未列出的改动点不算授权）。
- **允许新建的文件，仅此 4 类**：会话令牌迁移 SQL、会话令牌仓储、过期清理脚本、后端契约与单元测试。
- **明确禁止**：不改 JWT 签发/校验、不改成员与工作区服务、不改任何摄取/检索/问答服务、不改发布事务、不改检索读取仓储、不改既有视图、不改其它业务路由内部、不加新依赖。

**文档侧**
- 鉴权相关的技术设计文档与安全设计文档各补一份记录，状态先写「提议」直到用户确认；不改写历史决策正文。这两份是文档同步产物，不计入上面的代码文件数。

**其它子项目**
- 权限角色模型扩展、服务端首屏取数、可观测性、持续集成与容器加固，本次一律不碰。

**越界判定**：任何不落在上述白名单的改动，或把某个决策再拆成多节施工规格、或重新翻查无关目录，都算跑偏，立即停。
