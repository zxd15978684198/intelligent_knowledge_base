## 4. 接口约定

- 会话 Cookie 三件套：访问（HttpOnly、Lax、根路径、1 小时）、刷新（HttpOnly、Lax、限定鉴权路径、绝对 7 天、不滑动延长）、CSRF（前端可读、Lax、根路径、按会话稳定不随刷新轮换）；安全标记只在生产类环境开启。
- 端点：注册 201 / 登录 200 的响应体仍保留访问令牌并下发三件套；查我端点不变；刷新 200 只含有效期并下发访问 + 刷新两个 Cookie（不重发 CSRF）；登出 204 幂等并清三件套。
- 刷新算法：行锁读取；查不到、过期、主体停用、超宽限重用 → 撤销家族后 401；宽限内重复投递 → 204 且不带任何 Set-Cookie；正常 → 插入后继（复制家族、CSRF 哈希、绝对过期）+ 标记轮换 + 显式提交后再下发 Cookie。
- 事务纪律：失败分支必须在抛错前显式提交撤销，否则会话作用域的异常回滚会把撤销一起回滚；成功分支提交后再设 Cookie，避免事务回滚却发了会话。
- CSRF：安全方法跳过；无会话 Cookie 跳过（匿名端点与命令行 Bearer）；有则比对请求头与 Cookie；刷新端点额外校验 CSRF 哈希与库中一致。
