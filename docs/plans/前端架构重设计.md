## 1. 现状与问题

### 1.1 现状（描述对象 = 工作区已存在的前端代码）

- 技术栈：Next 16 App Router + React 19 + TypeScript；服务端缓存态用 TanStack Query v5；聊天用 Context + useReducer 独立状态机；UI 为自研基础组件 + 图标；样式为 Tailwind + CSS 变量；测试为 Vitest / MSW / Playwright / 无障碍扫描。
- 目录分层：`app/` 路由与页面，`features/` 七个业务域（鉴权、聊天、文档、作业、知识库、成员、检索），`components/` 基础组件与应用外壳，`lib/` 数据请求、会话、契约，`contracts/` 接口描述，`tests/` 分层测试。
- 网络拓扑：浏览器只访问前端端口；同源转发把接口、健康检查、接口描述、文档与静态资源代理到后端。构建产物为 standalone 模式，转发目标在构建期确定。
- 鉴权现状：登录后把访问令牌写入浏览器本地存储；数据请求层自动注入 Bearer 头；流式应答单独手工注入同一个头；「本地有无令牌」同时充当登录态判据；跨标签页靠 storage 事件同步。

### 1.2 架构层面的问题

| # | 问题 | 影响 |
| --- | --- | --- |
| P1 | 凭据与登录态耦合在本地存储令牌上 | 页面内任意脚本可读；登出只是客户端丢弃；令牌在有效期内不可撤销；一个字段承担三个职责 |
| P2 | 身份真值源不唯一 | 登录态、请求凭据、跨标签页同步三处各自判断，容易出现「界面显示已登录但请求 401」 |
| P3 | 契约层分叉 | JSON 请求与流式应答两套解析路径，错误体、事件顺序、请求标识各写一遍 |
| P4 | 渲染层次单一 | 页面全在客户端取数，首屏要等脚本水合 |
| P5 | 可观测性与交付缺口 | 前端无请求标识串联、无错误上报、无流式性能指标；前端门禁未进持续集成、一键起栈未实跑 |
| P6 | 设计易漂移 | 决策散落在会话与实现两处，缺少单一架构基线 |

本文只解决 **P1 / P2 / P3 / P6**，并为它们划定边界；**P4 / P5 明确列为后续演进**，不混进本次实施。

## 2. 目标架构（分层与模块边界）

### 2.1 层次（自上而下，依赖单向）

| 层 | 职责 | 允许依赖 | 禁止 |
| --- | --- | --- | --- |
| L0 运行时与构建 | 路由框架、standalone 产物、同源转发 | 无 | 承载业务逻辑 |
| L1 路由与渲染 | 路由组、布局、页面编排、加载与错误边界 | L0 | 直接发请求、写业务状态 |
| L2 领域 | 七个业务域各自的类型、接口、钩子、组件 | L1、L3、L4、L5 | 横向引用其它领域内部、反向依赖下层 |
| L3 状态 | 服务端缓存态、流式会话态、会话身份态 | L4 | 把本地存储或 DOM 当真值源 |
| L4 数据访问 | 请求、上传、流式三个入口，查询键，401 续期横切 | L5 | 吞取消错误、业务请求重试 |
| L5 契约 | 生成类型、错误信封、流式事件、请求客户端 | L0 | 手写生成物、手写 multipart 头 |
| L6 质量 | 单元、契约、端到端测试，类型检查，构建，门禁 | 全部 | 被运行时反向依赖 |

依赖规则：只允许上层依赖下层；同层领域之间只通过各自公开出口；共用文件只追加，不改既有导出语义。

### 2.2 模块边界

| 目录 | 归属 | 职责 | 明确边界 |
| --- | --- | --- | --- |
| `app/` | 路由层 | 页面编排、布局、守卫 | 页面不放取数细节 |
| `features/<域>/` | 领域层 | 该域的 api / hooks / components / types | 不跨域引用内部文件 |
| `components/ui` | 组件层 | 无业务语义的基础组件 | 不读会话、不发请求 |
| `components/app-shell` | 组件层 | 导航、用户块、骨架屏、跳过链接 | 只消费身份，不判断登录 |
| `lib/api` | 数据访问层 | 请求、上传、流式、续期 | 唯一的 HTTP 出口 |
| `lib/auth` | 状态层 | 会话身份、跨标签页广播 | 不存令牌 |
| `lib/contracts` | 契约层 | 生成类型与事件定义 | 生成物不手改 |
| `contracts/` | 契约层 | 接口描述 | 变更后重跑生成 |
| `tests/` | 质量层 | 分层测试 | 端到端造数可保留 Bearer 兼容 |

### 2.3 架构不变量

- 身份解析只有一个入口；工作区只能在已加入的空间里选；查不到与无权返回同一种「不存在」语义。
- 发布、检索、问答等既有业务链路不因本次重设计改变语义。
- 迁移只追加；既有表、视图、已合并脚本不改写。
- 错误一律走统一错误体，携带请求标识。

## 3. 路由与渲染

- 两个路由组：公开组（登录）与受保护组（业务页）。受保护组在最外层套守卫与外壳：未登录跳转公开组，加载中渲染骨架屏。
- 页面只做编排：取数、状态、事件处理下沉到领域层；页面不直接拼请求。
- 布局负责持久外壳；知识库详情页用嵌套布局承载子页（文档、检索、聊天）。
- 渲染不变量：聊天状态机里「回答流是否结束」由独立的「仍等待结束事件」标志判定，而不是阶段字段；出错后仍会等到结束事件。流式应答页可切换宽屏并排布局，但不改变事件语义。
- 服务端首屏取数**本次不做**：它依赖会话态能在服务端读取，属于后续演进；本文只在层次里为它留位置，不提前造框架。
- 构建产物 standalone：转发目标在构建期求值，部署期注入；本次不改转发规则与产物模式。

## 4. 状态与数据流

### 4.1 三类状态，三个真值源

| 状态 | 载体 | 真值源 | 禁止 |
| --- | --- | --- | --- |
| 服务端缓存态 | 查询缓存 | 后端响应 | 把「有无令牌」当缓存有效性 |
| 流式会话态 | 独立 reducer | 事件序列 | 用阶段字段代替「仍等待结束事件」 |
| 会话身份态 | 上下文 | 探活结果 | 从本地存储读登录态 |

查询键必须包含工作区；工作区切换后旧键数据不得串到新工作区。

### 4.2 主要数据流

- 上传：表单 → 上传入口 → 按响应状态区分「新文档」与「去重命中」，两条分支都走同一错误信封。
- 处理：作业轮询到终态；终态判定按既有作业状态语义，不把「被取代」误判为终态。
- 发布：单事务内完成版本切换，前端只展示结果，不参与事务。
- 检索与问答：检索走 JSON；问答走流式，事件顺序固定为「检索结果 → 若干增量 → 结束」，错误之后仍必有结束事件。
- 血缘：只展示版本链，不伪造时间字段。

### 4.3 横切纪律

- 401 续期放在数据访问层，作为唯一横切点：单个请求失败才触发，并发只放出一个刷新，成功后原请求重放一次。
- 明确排除：上传请求、已开流的流式应答、刷新请求自身，都不参与重放。
- 业务请求本身不重试；取消错误不吞；本地存储令牌删除后，登录态改由探活结果与跨标签页广播驱动。

## 5. 契约层

- 单一来源：接口描述生成 TypeScript 类型；手写类型只用于流式事件与错误信封。生成物不手改。
- 统一错误体：`{error:{code,message,retryable,details}, request_id}`；客户端错误对象携带状态、错误码、详情与请求标识。
- 流式事件：客户端自己按流解析，不复用 JSON 请求通道；错误事件后必有结束事件；结束事件里的无效引用数为整数。
- 契约口径（前端必须按此消费，不自行脑补字段）：作业状态含「被取代」且它不算终态；分页总数指本页条数；成员列表键固定；文档详情不含创建时间；乐观锁缺头返回前提缺失；上传两种响应状态语义不同。
- 变更纪律：新增端点或错误码后必须重跑类型生成；不手写生成物；不新增第二套错误解析。

## 6. 鉴权与会话

> 本章把四项已确认决策压成**一章架构描述**。实施级细节留给阶段计划，本文不展开成施工规格。

### 6.1 目标与显式取舍

- 目标：把访问令牌从浏览器本地存储迁到 HttpOnly 会话 Cookie，并让会话可被服务端撤销；同时保住命令行工具与评测脚本的 Bearer 用法，以及上传、轮询、流式三条既有链路。
- 显式取舍一：登录与注册响应体仍保留访问令牌（供命令行与评测脚本），代价是登录那一瞬页面脚本仍可读到它；Cookie 的价值在于此后任何页面脚本读不到持久凭据。
- 显式取舍二：解析失败的错误文案保持原样，避免契约抖动。
- 显式取舍三：刷新失败时服务端不主动清 Cookie，交给前端幂等登出收尾。

### 6.2 四项决策与各自的边界

| # | 决策 | 架构位置 | 允许改动 | 明确不改 |
| --- | --- | --- | --- | --- |
| ① | 后端直供 Cookie | 契约层 + 后端鉴权路由 | 注册与登录下发会话 Cookie；新增刷新、登出端点；一个只含有效期的刷新响应模型；两个 Cookie 读写 helper；新增会话有效期配置与安全 Cookie 判定；配置样例补一行 | 三个既有端点的响应字段、登录失败与重名语义、令牌签发与校验函数 |
| ② | 落库 + 单次轮换 + 重用检测 | 新增独立存储 | 一张会话令牌表（只存哈希、家族、主体、CSRF 哈希、绝对过期、轮换、后继、撤销时间）与两个索引；一个六方法仓储；一个手动清理脚本；表映射末尾追加一类；测试清理清单加一行 | 既有迁移脚本、既有表与视图、工作区列、自引用外键、调度器与缓存 |
| ③ | 401 触发 + 单飞队列 + 原请求重放 | 数据访问层（纯前端） | 请求层、会话层、鉴权状态层、流式建流段、成员域鉴权传参及其测试；删除本地令牌存储模块与其单测 | 后端零改动；上传、已开流、刷新自身排除重放；状态机「出错后仍等结束事件」不变量 |
| ④ | SameSite=Lax + 双提交 CSRF Token | 后端依赖层 | 追加一个 CSRF 错误码与一条 403 映射；末尾追加一个校验依赖；令牌解析只换三行（有 Cookie 用 Cookie、无则 Bearer 兜底）与文件头注释；八个非鉴权路由注册处各挂一行依赖 | 工作区选择、成员校验、数据上下文、作用域对象、权限与资源访问校验；解析失败文案 |

因果链：① 改 Cookie 引出跨站伪造风险 → ④；① 会过期引出续期 → ③；③ 要求可撤销 → ②；② 的重用检测反过来逼 ③ 必须单飞，否则并发刷新会把整个会话家族撤销。CSRF 值按会话稳定、不随刷新轮换，否则重放在途请求会带旧值失败。

### 6.3 白名单封顶

- 后端既有文件**仅 8 个**：鉴权路由、依赖入口、错误码、配置、应用注册、表映射、测试清理夹具、配置样例。
- 后端新建**仅 4 类**：迁移脚本、仓储、清理脚本、契约与单元测试。
- 前端：数据访问、会话、鉴权状态、流式建流、成员传参及其测试；删除项仅限本地令牌存储模块与其单测。
- 文档同步：鉴权相关的技术设计记录与安全设计记录各补一份，状态先写「提议」直到确认，不改写历史决策正文。这两份是文档产物，不计入上面的代码文件数。
- 明确禁止：令牌签发校验、成员与工作区服务、摄取/检索/问答服务、发布事务、检索读取仓储、既有视图、其它业务路由内部、新依赖、转发配置与产物模式。
- 其它子项目（权限模型扩展、服务端首屏取数、可观测性、持续集成与容器加固）本次一律不碰。

### 6.4 不变量与已知限制

- 身份解析唯一入口；工作区只在已加入空间里选；不泄漏「存在但无权」；迁移只追加；错误走统一信封。
- 已知限制（如实登记，不假装已解决）：过期会话行无调度器自动清理，靠顺带清理与手动脚本；接口文档的授权填框会被会话 Cookie 遮蔽；登录瞬间响应体仍含令牌；生产需要 HTTPS 终止层；跨标签页选主需真实浏览器核验；并发宽限时序难以完全复现。

## 7. 可观测性 / 交付 / 演进路线

> 本节只写**定位、依赖与顺序**，不写实施方案；除鉴权会话外，三项均标注「本次不做」。

| 子项目 | 定位 | 本次 | 依赖 |
| --- | --- | --- | --- |
| 鉴权会话 | 本文第 6 章 | **做** | 无 |
| 可观测性 | 请求标识全链路串联、前端错误上报、流式首字与断流与性能指标 | 不做 | 独立 |
| 交付加固 | 前端门禁进持续集成、容器健康检查、一键起栈、回滚演练 | 不做 | 独立 |
| 服务端首屏取数 | 会话态可在服务端读取后，把首屏取数上移 | 不做 | 依赖鉴权会话 |

演进顺序：鉴权会话 → （可观测性 ∥ 交付加固）→ 服务端首屏取数。后端先上线（Cookie 优先 + Bearer 兜底），旧前端继续可用，再切前端，无需额外功能开关。

## 8. 分步迁移、验收与回滚

### 8.1 迁移阶段

| 阶段 | 内容 | 顺序约束 |
| --- | --- | --- |
| M0 | 只读登记工作树现状（不提交、不改动任何文件） | 最先 |
| M1 | 写本文并评审 | 先于代码 |
| M2 | 新增会话令牌表与仓储（只追加迁移） | 先于后端逻辑 |
| M3 | 后端配套改动上线 | 先于前端；旧前端靠 Bearer 兜底继续可用 |
| M4 | 前端切换与本地令牌存储下线 | 不早于 M3 |
| M5 | 契约、单元、前端测试补齐 | 与 M3、M4 同步收口 |
| M6 | 全量验收与进度记录收尾 | 最后 |

### 8.2 降级与回滚

- 降级：Bearer 兜底即天然降级路径，不需要额外开关。
- 代码回滚：回退对应提交即可，不改写历史。
- 镜像回滚：切回上一版镜像，先确认旧代码能读新库。
- 数据库不回滚：迁移只追加，不删表、不跑破坏性清理。
- 紧急作废会话：把所有会话令牌家族标记为撤销，强制全部重新登录。

### 8.3 验收

- 门禁：静态检查、单元测试、契约测试、接口测试、集成测试、类型检查、前端测试、构建，全部通过并贴真实输出。
- 范围验收：逐文件核对，后端改动全部落在 6.3 的白名单内，无一处越界。
- 人工核验：浏览器脚本读不到会话 Cookie；刷新页面仍保持登录；两个标签页并发只触发一次刷新；跨站写请求被 403 拦下。
- 进度记录：每完成一个阶段就更新，状态与进度一致，未验证项如实列出。

### 8.4 未验证项汇总

跨标签页选主、真实浏览器会话行为、容器一键起栈、生产 HTTPS 终止层、并发宽限时序、接口文档授权填框遮蔽、过期行清理。以上按实际环境标注，不写「通过」。
