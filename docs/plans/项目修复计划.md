## 1. 现状（核查结论）

### 1.1 环境：三处不一致，是当前"跑不起来"的直接原因

| 项 | 应有 | 实际 | 后果 |
| --- | --- | --- | --- |
| 数据库端口 | `5433`（`src/pyknora/core/settings.py:12` 默认值） | `5433` 被 **phase0 项目**的 `pyknora-phase0-postgres-1` 占用（`POSTGRES_USER=pyknora`、密码 `phase0-local-only`） | 以 `postgres/dev` 连 → `InvalidPasswordError: password authentication failed for user "postgres"` |
| 可用数据库 | 容器 `pyknora-pg` | 实际是 `pyknora-pg-p0`（pgvector/pg16，映射 `0.0.0.0:5434->5432`，`postgres/dev`） | 默认配置连不上；可用库在 **5434** |
| 迁移目标容器 | `settings.db_container = "pyknora-pg"`（`settings.py:13`） | 同名容器不存在 | `scripts/migrate.py` 必然失败 |

`pyknora-pg-p0` 上的库**结构是对的**（已应用到 0005）：17 个关系 = 16 表 + `v_active_chunks`；
`index_migrations_pkey = PRIMARY KEY (workspace_id, migration_id)`；
`documents_kb_fk = FOREIGN KEY (workspace_id, kb_id) REFERENCES knowledge_bases(workspace_id, kb_id) ON DELETE RESTRICT`。

### F5 · 无网也能跑通的 embedding 开关（P0，5 分钟）

- **现象**：默认 `embedding_backend=local`，首次 query 会去下 `BAAI/bge-small-zh-v1.5`（几百 MB）。没网/超时就表现为 query 卡住。
- **改法**：跑通链路时在 `.env` 加一行 `PYKNORA_EMBEDDING_BACKEND=hashing`（`HashingEmbedder` 已存在，512 维，不截断）。
- **红线**：`hashing` **只用于跑通验证**，不能当交付口径——它的向量没有语义，检索质量不能作为验收证据。真正验收前必须切回 `local` 并证明权重已就绪。
- **✔ 2026-10-29 完成（Lead 裁决，提交 sha：未提交）**。证据：`hashing` 后端被 `scripts/seed_for_m3.py`（30 chunk）与整条烟测（A1–A9 **14/14**）实际使用，**无网路径已验证跑通**（`HashingEmbedder` 512 维、不截断，与 `dim=512` 一致）。
- **同时必须记住的未验证项**：① `.env` 里是否已固化 `PYKNORA_EMBEDDING_BACKEND=hashing` **无法独立读取核对**（读取被 CC Safety Net 拦，Rule `secret.basename.env`）；② `local`（`BAAI/bge-small-zh-v1.5`）与 `openai` 两个真实后端**仍未跑**。
- 上面的红线**不变**：`hashing` 只用于本地跑通与测试，交付口径必须是 `local` / `openai`。
