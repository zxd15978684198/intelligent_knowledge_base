## 0. 先看这一页（3 分钟）

| 维度 | 事实 |
| --- | --- |
| 项目定位 | 企业智能知识库：**增量索引** + **权限隔离**（课件 Day2 主线） |
| 技术栈 | Python 3.12 / FastAPI / SQLAlchemy 2.0 async / asyncpg / PostgreSQL 16 + pgvector / pydantic v2 / uv |
| 队列选型 | **PG 业务表 + `FOR UPDATE SKIP LOCKED`**，不引入 Redis/Celery（裁决 D1） |
| 向量后端 | 本地 HuggingFace（`BAAI/bge-small-zh-v1.5`，512 维）或 OpenAI 兼容 HTTP，二选一（裁决 D2） |
| 当前代码覆盖 | **五个人的交付面都已落地**（上传→解析→切片→向量→发布+队列+Worker / 知识库 CRUD / 检索与 RAG / JWT+membership+RLS / 来源追踪）；仍缺的只有 §8 那几项 |
| 目录树覆盖谁 | **两棵树**：§1.1 是 `ls` 看得到的现状（五人的文件都在）；§1.2 是**全员目标结构**（🔜 = 还没建）；§1.3 是每人"只改这几行"的切片 |
| 目录结构 | 纳入版本管理的一级目录 8 个（`src` `tests` `migrations` `scripts` `docs` `references` `.githooks` `.github`）；`src/pyknora/` 下 7 个子包 |
| 代码规模 | `src/pyknora/` 下 **62 个实模块**（非 `__init__.py` 且非空；另有 20 个 `__init__.py`，其中 17 个为空）；测试 **79 个 `test_*.py` / 1158 个用例**（单元 889 / 契约 20 / API 170 / 集成 79）。2026-11-09 实测：模块数按文件计，用例数按 `uv run pytest --collect-only -q <目录>` 逐文件求和（`-q` 不打印合计行） |
| 数据库 | `migrations/0001–0016`（16 个文件）现共 **17 张表 + 1 个视图**（`0001_init.sql` 建其中 9 张；0007 中文 bigram FTS 函数、0008 角色转数据、0011 RLS 补墙、0012 视图跳过已删库、0013 跨页切片的结束页 `chunks.page_end_no`、0014 切片 `locator`、0015 `refresh_tokens`、0016 文档有效期只加列不建表）；ORM 映射 **16 张**（只有 `outbox` 无 Row、走原生 SQL；`index_migrations` 有 `IndexMigrationRow`） |
| 一句话架构 | HTTP 层只做校验，业务全在 `services/`，可见性由**数据库视图**保证，发布是**单事务** |

### 3.3 可见性怎么保证（最重要的一条设计）

`migrations/0001_init.sql:236` 的视图 `v_active_chunks` 把"只看活动版本"写进结构：

```
WHERE d.active_build_id = b.build_id AND b.state = 'active'
  AND d.deleted_at IS NULL AND c.embedding IS NOT NULL
```

因为 JOIN 的是 `documents` 的活动指针，**staging / retired 的 chunk 在物理上不可见**，调用方忘写条件也不会读到旧索引。视图额外投出 `kb_id`（省一次 join）与 `embedding_dim`（供检索前校验，**视图本身不校验维度**）。

## 7. 读代码时要注意的 9 个坑与不一致

这些是我实测发现的、**会让人误判**的地方，先记住能省半天：

| # | 现象 | 真相 |
| --- | --- | --- |
| 1 | 觉得 `/health` 里 `kb_repo: null` = 上传 503 | 早就不成立：`api/deps.py:117-131` 未注入时回落 `SqlKnowledgeBaseRepo(session)`；`null` 只说明按请求构造 |
| 2 | 视图里 `embedding_dim` 看着像校验 | 视图只投出这一列，**校验在 `SqlChunkSearchRepo.search_similar`**（`db/repos/reads.py:239`）；不校验会变成 PG 维度异常（500） |
| 3 | 切片 `content` 做过 `strip()` | 只删首尾空白，**禁止内部空白折叠**，否则 `char_start/char_end` 拼不回原文（真实踩过） |
| 4 | 跨区测试"永远通过" | 第一版 `FakeKbRepo` 收下 `scope` 就丢掉；现在按 `(workspace_id, kb_id)` 存，跨区返回 `None` |
| 5 | 集成测试偶发 `ScopeMismatch` / 坏连接 | 异步夹具必须 `function` 作用域，且每例 `dispose_engine()`（连接池绑在创建它的事件循环上） |

| 7 | `db/repos/reads.py` 反向依赖 `services.ingest.embedder` | `db/repos/reads.py:25` 只有 `EmbeddingDimensionError` 一个符号，建议搬进 `core/errors.py` |
| 8 | `pyknora` 命令只打印 Hello | `src/pyknora/__init__.py` 仍是脚手架残留，别把它当 CLI 入口设计 |
| 9 | 流式端点里抛 `AppError` | `StreamingResponse` 一旦开始发就改不了状态码，生成器里抛异常会让 Starlette 撞 `"response already started"`，客户端只见 `httpx.RemoteProtocolError`（连错误体都没有）。失败要降级成 SSE 的 `error` 事件再补 `done`（参照 `services/rag/answer.py:86-98` 与 `tests/api/test_api_chat.py`）；建流**之前**能判的（没配 key、没注入 embedder）必须提前抛成 503，别拖进流里 |

## 附：命名与提交约定（从现有代码归纳）

- **文件**：模块用小写单词（`embedding_service.py`、`ingest_worker.py`），不用驼峰、不用复数。
- **目录**：按技术角色分层（`api/db/models/schemas/services/workers`），不按业务域分。
- **函数**：动词开头且体现意图（`upload_document`、`claim`、`publish`、`purge_document_chunks`）；纯函数与副作用分开（`parser`/`splitter` 不碰 DB）。
- **docstring**：解释**为什么**，特别是"这么写会踩什么坑"；每个踩过的坑都留在注释里（本仓库最值得学的一点）。
- **迁移**：手写数字号段 `000N_主题.sql`，不用 alembic；改表只新增文件，不改历史文件。
- **测试**：单元测纯函数与语义红线，集成测 PG 特有行为；**不用 SQLite 替身**。
