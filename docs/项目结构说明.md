### 1.4 共用文件的冲突规则（五个人都会碰的地方）

| 共用物 | 为什么危险 | 约定 |
| --- | --- | --- |
| `api/main.py` | 五个人的路由都在这挂 | 只在 `include_router` 区域**追加一行**，不重排别人的行；合并冲突按"成员序号小的在前"重排 |
| `models/tables.py` | 一文件装所有人的表映射 | **追加式**：新类加在文件末尾，公用导入不重排 |
| `services/contracts/reads.py` | 改签名等于改全员契约 | 改动 = 提交前在群里过一遍；只加方法不改已有方法签名 |
| `migrations/` 号段 | 两个人同时拿 `0002` 必冲突 | 抢号：先合并者用当前最大号 +1；**已合并文件不改**，改表就新增 |
| `tests/integration/conftest.py` 的 `TABLES` | 漏加自己的表 → `TRUNCATE` 清不到，测试互相污染（间歇性红） | 建表的同时把自己的表名加进 `TABLES` |
| `core/scope.py` / `core/errors.py` | 全员依赖 | 只允许"加枚举/加方法"，不允许改已有语义（尤其 `owns(None) is False`） |

## 2. 逐目录解释

### 2.1 根目录

| 路径 | 作用 | 改它要注意 |
| --- | --- | --- |
| `pyproject.toml` | 唯一依赖与工具配置处（pytest `testpaths`、`asyncio_mode="auto"`、ruff `line-length=100`） | 加依赖走 `uv add`，顺手更新 `uv.lock` |
| `uv.lock` | 锁文件 | 不要手改 |
| `.gitmodules` + `references/WeKnora` | 对标项目（腾讯 WeKnora）子模块 | `.gitignore` 里有 `references/**`，**子模块内容不入主库**；未 `submodule update` 时该目录是空的 |
| `README.md` | 快速开始 + 三条不变量 + 目录速查 | 不变量改了要同步这里 |
| ~~`AGENTS.md`~~ | **已被删除**（`git status` 显示 `D AGENTS.md`，磁盘上不存在） | 老文档里"写进 AGENTS.md"的说法属历史，别照着找 |

### 2.2 `src/pyknora/` 七个一级子包

| 子包 | 职责（一句话） | 关键文件 | 红线 |
| --- | --- | --- | --- |
| `api/` | 对外 HTTP 面，只做参数校验 + 调 service + 组装响应 | `main.py`（应用工厂）、`deps.py`（★权限唯一入口）、`v1/{documents,jobs}.py` | **不允许写业务 SQL**；身份只能从 `deps.get_scope` 来 |
| `core/` | 无框架依赖的地基：配置、作用域、错误码 | `settings.py:8`、`scope.py:14`、`errors.py:12` | `core` 不得 import 任何上层模块 |
| `db/` | 引擎/会话 + 读契约实现 | `session.py:46`（`session_scope`）、`repos/reads.py` | 读操作**一律走 `v_active_chunks` 视图**，不在 Python 拼 WHERE |
| `models/` | 表结构映射 | `tables.py`（8 张） | 与 `migrations/*.sql` 必须同步改 |
| `schemas/` | 跨模块数据形状（pydantic） | `kb.py`、`document.py`、`chunk.py` | 不依赖 `db` / `api` / `services` |
| `services/` | 业务逻辑 | `contracts/reads.py`、`ingest/*`、`queue/jobs.py` | 跨模块只通过 `contracts/` 里的 Protocol 通信 |
| `workers/` | 独立进程入口（不走 HTTP） | `ingest_worker.py` | 与 `api/` **不互相 import** |

### 3.3 可见性怎么保证（最重要的一条设计）

`migrations/0001_init.sql:201` 的视图 `v_active_chunks` 把"只看活动版本"写进结构：

```
WHERE d.active_build_id = b.build_id AND b.state = 'active'
  AND d.deleted_at IS NULL AND c.embedding IS NOT NULL
```

因为 JOIN 的是 `documents` 的活动指针，**staging / retired 的 chunk 在物理上不可见**，调用方忘写条件也不会读到旧索引。视图额外投出 `kb_id`（省一次 join）与 `embedding_dim`（供检索前校验，**视图本身不校验维度**）。

- **函数**：动词开头且体现意图（`upload_document`、`claim`、`publish`、`purge_document_chunks`）；纯函数与副作用分开（`parser`/`splitter` 不碰 DB）。
- **docstring**：解释**为什么**，特别是"这么写会踩什么坑"；每个踩过的坑都留在注释里（本仓库最值得学的一点）。
- **迁移**：手写数字号段 `000N_主题.sql`，不用 alembic；改表只新增文件，不改历史文件。
- **测试**：单元测纯函数与语义红线，集成测 PG 特有行为；**不用 SQLite 替身**。
